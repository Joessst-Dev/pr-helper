# PR Helper

Tauri 2 desktop app (Rust backend in `src-tauri/`, React + TS + Tailwind v4 frontend in `src/`) that lists open PRs/MRs on connected GitHub/GitLab servers and reviews them with a headless Claude Code session.

The user runs and builds the app on **macOS**. A Linux sandbox may be used only to compile and test.

## Commands

- `npm run tauri dev`: run the app
- `npm run check`: tsc + vitest + rustfmt + clippy (`-D warnings`) + cargo test. Must stay green.
- `cd src-tauri && cargo test real_claude -- --ignored --nocapture`: end-to-end review with the real `claude` CLI (haiku, costs cents)
- TS types in `src/lib/bindings/` are generated by ts-rs during `cargo test`. Never edit them by hand. Annotate `u64` fields with `#[ts(type = "number")]`.

## Architecture (src-tauri/src)

- `commands.rs`: thin Tauri command layer. Typed wrappers live in `src/lib/api.ts`. Keep both in sync.
- `service.rs`: shared state. All UI side effects go through the `UiSink` trait so the logic is testable without Tauri.
- `providers/`: the `GitProvider` trait, plus `github.rs` (GraphQL search + REST reviews) and `gitlab.rs` (v4 discussions/approve). Tests use wiremock.
- `git/repo_cache.rs`: bare clone per repo, worktree per review. The token goes through `GIT_CONFIG_*` env (`http.extraHeader`), never on disk.
- `git/diff.rs`: unified diff index for anchoring inline comments (right = new lines, left = removed lines).
- `review/`:
  - `queue` handles concurrency and per-PR dedupe/supersede.
  - `pipeline` runs one review.
  - `runner` spawns `claude -p` (stream-json + `--json-schema`).
  - `postprocess` enforces the comment rules.
  - `post` posts the selected findings.
  - `skills` packages configured skills as a `--plugin-dir` plugin.
- `watcher.rs` polls tracked PRs. `decide()` is the pure decision logic.
- `settings.rs` resolves settings in the order defaults → global → server → repo.

## Project skills (`.claude/skills/`)

Project-specific (ours, edit freely): `comment-rules`, `security-invariants`, `add-git-provider`, `add-review-setting`, `add-tauri-command`, `verify-changes`. Load the matching one before working in that area.

Public skills, installed with `npx skills` and pinned in `skills-lock.json` (don't edit them; `npx skills update -p` refreshes them, `npx skills experimental_install` restores them):
- `tauri-v2` (Tauri 2 commands, IPC, capabilities, plugins, distribution)
- `rust-best-practices` (Apollo)
- `rust-async-patterns` (tokio)
- `vercel-react-best-practices` (only the client-side rules apply; this is not Next.js)
- `tanstack-query-best-practices`
- `vitest`

Where a public skill conflicts with this file or a project skill, this file wins (e.g. the comment and security rules).

## Hard rules (enforced in `review/postprocess.rs`, never only in prompts)

- Proposed comments never contain `--`, em dashes or en dashes in prose. Inline code, fenced code and URLs are exempt.
- When `forbid_ai_attribution` is on (the default), no AI/Claude attribution of any kind, and no footers.
- Findings are sorted by severity: critical > high > medium > low > nit. `skip_nits` drops nits.
- `finalize_body` runs again on user-edited text right before posting.
- An approve verdict with any medium-or-higher finding is downgraded.

## Tokens

API tokens are stored only in the OS keychain (`secrets.rs`, macOS Keychain via `keyring` apple-native). They are never in SQLite, logs, files, git config or argv. `Service::save_server` is the only write path. Tests scan the raw DB files for the token.

## Reviewer isolation

The PR checkout is untrusted. The runner must keep `--setting-sources user` (otherwise the PR's `.claude/settings.json` hooks execute; verified), `--strict-mcp-config`, and `--tools Read Grep Glob Skill`. The reviewer has no Bash and no write access. Review material (diff, commits, description) goes into a context dir passed with `--add-dir`.
